# Bustem visitor recovery

Use this repository's [README](../../../README.md), [connection map](../../../docs/INTEGRATIONS.md), and [workflow contract](../../../public/workflow-template.json) to understand the demo. Treat every live integration as a proposal until Bustem confirms its setup.

When asked to review a run, identify the visitor, form submission, actual report sent record, return or booked call, and account outcome. Report missing events as unknown, not as completed steps. The demo's two minute timer is for illustration; ask the operator for the production delay.

For a quiet report account, prepare a short draft tied to the verified report finding and show the report entry. Keep it a draft for human review. Do not send messages, infer a person's role from a LinkedIn slug, or contact an anonymous form starter. A company match is not an individual identity.

For a manually sent report, use the operator's **Record report sent** action or the spreadsheet schema in the connection map. Never count a form submission as report delivery. Before connecting live data, require authorized access, protected endpoints, and verified webhook sources.
